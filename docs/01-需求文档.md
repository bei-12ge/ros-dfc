## 1. 项目背景

ROS（Robot Operating System）是机器人领域主流的分布式通信框架，其核心是**节点（Node）与话题（Topic）的松耦合通信模型**：发布者节点向某个话题写消息，订阅者节点从该话题读消息，双方互不感知对方的存在，由中心的管理模块完成路由。这是机器人多模块协同工作的基础。

本次课程以 C++ 学习为背景，同时面向后续比赛中的 ROS 实战需求，要求**不使用真实 ROS 的 API**，用 C++ 复刻 ROS 最核心的通信逻辑。因此本项目的本质是：**用一套可编译、可测试、可扩展的 C++ 代码，抽象并实现"发布/订阅"这一设计模型**，重点检验 C++ 的封装、继承、多态、资源管理与异常处理水平。

## 2. 项目目标

1. **功能目标**：在一个进程内实现与 ROS 语义一致的节点注册、话题发布、消息转发、订阅回调、全局关闭的完整生命周期。
2. **工程目标**：代码遵循严格 C++ 编码习惯（C++17、RAII、无裸 new/delete、编译零警告），配套需求、架构、技术、用户、测试五类文档。
3. **工程过程目标**：以 Git 增量提交体现"一个小功能一次提交"的开发轨迹，而非一次性堆代码。
4. **能力目标**：让使用者能仅阅读用户手册，就在 5 分钟内写出自己的第一个发布者与订阅者。

## 3. 范围

### 3.1 范围内（In Scope）

- 单进程内的节点/话题/消息模型与消息路由；
- 节点基类的统一行为规范（命名、初始化、关闭）；
- 发布者、订阅者两类节点；
- 消息封装与时间戳生成；
- ROS 核心管理模块（单例、映射维护、消息转发、全局关闭）；
- 异常体系与分级日志（控制台 + 文件）；
- 加分项：自定义传感器消息、服务/客户端同步通信、运行时动态增删节点、日志持久化、自定义异常分级处理；
- 单元/集成/并发测试与命令行演示程序。

### 3.2 范围外（Out of Scope）

- 真实 ROS 的 API、消息包（`.msg`）、`roscore`、`rosbag`、TF、参数服务器、ActionLib；
- 跨进程/跨主机通信（TCPROS、共享内存、DDS），本项目为单进程内存模型；
- 图形界面、可视化（rviz 类工具）；
- 消息序列化协议与网络传输可靠性（QoS、重传、心跳）；
- 权限、鉴权、安全机制。

> 说明：范围外的能力在架构上预留了扩展点（见《02-架构设计文档》第 9 章），但 v1 不实现。

## 4. 术语定义

| 术语 | 定义 |
| --- | --- |
| 节点 Node | 系统的最小功能单元，分为发布者节点与订阅者节点，每个节点有唯一名称 |
| 话题 Topic | 节点间通信的"通道"，发布者向话题发消息，订阅者从话题收消息 |
| 消息 Message | 通信的数据载体，包含业务内容和时间戳 |
| 发布者 Publisher | 向指定话题发布消息的节点 |
| 订阅者 Subscriber | 订阅指定话题并接收消息的节点 |
| 单例模式 Singleton | 保证 ROS 核心管理类全局仅有一个实例 |
| 回调 Callback | 订阅者收到消息后由框架调用的用户函数 |
| 分级日志 | 按 INFO / WARN / ERROR 三个级别分类输出的运行日志 |
| 同步请求-响应 | 客户端调用服务后阻塞等待服务端返回结果（加分项） |

## 5. 用户与使用场景

| 角色 | 关注点 | 典型操作 |
| --- | --- | --- |
| 学生（开发者） | 代码质量、可扩展、能讲清设计 | 阅读架构文档、二次开发自定义消息 |
| 助教/评审 | 需求是否被实现、异常是否稳健 | 运行测试用例、制造非法输入 |
| 使用者（比赛队友） | 能否快速接入自己的业务逻辑 | 按用户手册写 Publisher/Subscriber |

典型场景：`ros_demo` 演示程序启动 → 创建 2 个发布者、3 个订阅者 → 连续发布 20 条消息 → 订阅者打印带时间戳的接收日志 → 触发若干非法操作验证异常 → 全局关闭并落盘日志。

## 6. 功能需求

优先级：P0 = 必须实现（对应评分表 25 分代码项）；P1 = 加分项（对应 15 分）。

### FR-01 节点基类（P0）

系统必须提供所有节点的抽象父类 `Node`：

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-01.1 | 封装唯一的节点名称 | `name()` 只读返回构造时传入的名称，外部无任何修改入口 |
| FR-01.2 | 定义初始化接口与关闭接口为纯虚函数 | `init()`、`shutdown()` 为 `= 0`，子类必须实现 |
| FR-01.3 | 子类实现时输出初始化、关闭日志 | 运行日志中出现 `节点 xxx 初始化完成`、`节点 xxx 已关闭` |
| FR-01.4 | 空节点名必须被拒绝 | 构造空串/纯空白名称抛出 `NodeException`，错误码 `NODE-001` |

### FR-02 发布者节点（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-02.1 | 继承 `Node`，扩展话题名称属性及只读接口 | `topic()` 只读返回 |
| FR-02.2 | `init()` 输出初始化日志并向 ROS 核心注册自身 | 注册后 `ROS::publisherCount(topic) == 1` |
| FR-02.3 | `shutdown()` 输出关闭日志并从核心注销 | 注销后计数归零，重复 shutdown 不崩溃 |
| FR-02.4 | 核心发布功能：接收传感器字符串 → 创建 `Message` → 输出发布日志 → 转发至核心对应话题 | `publish("24.5")` 后订阅者收到内容为 `24.5`、带时间戳的消息 |
| FR-02.5 | 空话题名必须被拒绝 | 抛 `TopicException`，错误码 `TOPIC-001` |
| FR-02.6 | 空消息内容必须被拒绝 | 抛 `MessageException`，错误码 `MSG-001` |

### FR-03 订阅者节点（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-03.1 | 继承 `Node`，扩展话题名称属性及只读接口 | `topic()` 只读返回 |
| FR-03.2 | `init()` 输出初始化日志并向核心注册自身 | 注册后 `ROS::subscriberCount(topic) == 1` |
| FR-03.3 | `shutdown()` 输出关闭日志并注销 | 注销后不再收到消息 |
| FR-03.4 | 核心订阅功能：接收消息对象，输出**包含消息内容和时间戳**的接收日志 | 日志形如 `[接收] 节点 sub1 收到消息: 内容=24.5, 时间戳=2026-11-14 20:15:30` |
| FR-03.5 | 支持用户回调，便于业务扩展 | 注册回调后回调被调用，且能读取消息内容 |

### FR-04 消息封装类（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-04.1 | 封装字符串类型的消息内容 | `content()` 只读 |
| FR-04.2 | 自动生成 `YYYY-MM-DD HH:MM:SS` 格式的系统时间戳 | 正则 `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}$` 校验通过，且为当前本地时间（误差 ≤ 2 s） |
| FR-04.3 | 仅提供读取接口，保证封装性 | 无任何 setter；拷贝后内容不变 |
| FR-04.4 | 空/全空白内容拒绝构造 | 抛 `MessageException`，错误码 `MSG-001` |

### FR-05 ROS 核心管理模块（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-05.1 | 采用单例模式，全局唯一实例 | `&ROS::instance() == &ROS::instance()`，构造/拷贝/赋值被禁用 |
| FR-05.2 | 维护"话题 → 发布者"映射 | `publishersOf(topic)` 返回该话题全部发布者名称 |
| FR-05.3 | 维护"话题 → 订阅者"映射 | `subscribersOf(topic)` 返回该话题全部订阅者名称 |
| FR-05.4 | 提供发布者/订阅者注册方法以更新映射表 | 注册后映射与计数同步更新 |
| FR-05.5 | 消息转发：将指定话题的 `Message` 推送给该话题下**所有**订阅者 | 3 个订阅者全部收到，转发返回值为 3 |
| FR-05.6 | 统一关闭方法：遍历所有节点并执行其关闭方法 | `shutdownAll()` 后所有节点 `isRunning()==false`，日志按顺序出现 |
| FR-05.7 | 重复节点名注册必须被拒绝 | 抛 `NodeException`，错误码 `NODE-002` |
| FR-05.8 | 向不存在的话题转发必须抛出语义清晰的异常且不崩溃 | 抛 `TopicException`，错误码 `TOPIC-002` |

### FR-06 系统整体行为（P0）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-06.1 | 支持多个发布者、多个订阅者及其映射关系，并输出初始化日志 | 1 个话题可挂多个发布者与多个订阅者，日志齐全 |
| FR-06.2 | 发布者连续发布，无需等待订阅者响应（异步） | 发布耗时与订阅者数量无强相关（见 NFR-4），无阻塞等待应答 |
| FR-06.3 | 全生命周期：初始化 → 消息交互 → 关闭 | 演示程序完整跑通，无崩溃、无内存泄漏 |
| FR-06.4 | 任意非法输入不导致进程终止 | 演示程序内置 8 类非法操作，捕获后继续运行 |

### FR-07 加分功能（P1，对应评分表 15 分）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-07.1 | 自定义消息类型（含温度、湿度、时间戳的传感器消息） | `SensorMessage` 可发布，订阅端可读取 `temperature()`/`humidity()`，`typeName()` 为 `sensor_msgs/SensorData` |
| FR-07.2 | 服务/客户端同步请求-响应通信 | `ServiceClient::call(req)` 阻塞返回 `ServiceServer` 的处理结果；无此服务时抛 `ServiceException`（`SERVICE-001`） |
| FR-07.3 | 运行时动态添加/删除节点 | `ROS::removeNode(name)` 后该节点不再收到消息，其映射被清理 |
| FR-07.4 | 所有消息收发日志持久化写入文本文件 | 默认 `logs/ros_sim.log`，内容与控制台一致，含时间戳与级别 |
| FR-07.5 | 全局自定义异常处理机制：`NodeException`/`TopicException`/`MessageException` 等自定义异常类 + 全局捕获器 + 分级日志（INFO/WARN/ERROR） | 顶层 `try/catch` 捕获，控制台与文件均输出分类日志，错误码可查表 |

### FR-08 异常场景清单（P0）

以下操作必须抛出语义清晰的异常，且进程存活：

1. 空节点名 → `NODE-001`
2. 重复节点名注册 → `NODE-002`
3. 操作不存在/已关闭的节点 → `NODE-003`
4. 空话题名 → `TOPIC-001`
5. 向不存在的话题转发 → `TOPIC-002`
6. 空消息内容 → `MSG-001`
7. 空消息对象（`nullptr`）转发 → `MSG-002`
8. 调用不存在的服务 → `SERVICE-001`
9. 服务处理函数内部抛异常 → `SERVICE-002`（被服务层包装，不影响其他节点）
10. 日志文件不可写 → `std::runtime_error`（降级为仅控制台输出，不中断业务）

## 7. 非功能需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| NFR-1 | 编码规范 | C++17；遵循 RAII 与"谁申请谁释放"；不使用裸 `new`/`delete`（框架内部除外且必须有明确归属注释）；`-Wall -Wextra -Wpedantic` 零警告 |
| NFR-2 | 封装性 | 所有数据成员 `private`，只读属性通过 `const` 引用返回，类外不可写 |
| NFR-3 | 可维护性 | 单一职责，单文件单类；异常与日志集中管理；错误码集中在 `exception.h` 并有文档表 |
| NFR-4 | 性能 | 单话题 1 万次发布的转发耗时 < 100 ms；发布路径无 `sleep`、无锁等待订阅者 |
| NFR-5 | 线程安全 | 核心注册表用互斥量保护；回调在锁外执行，避免死锁；计数器使用原子类型 |
| NFR-6 | 健壮性 | 任何非法输入抛异常而非 `abort`/段错误；`shutdown` 幂等 |
| NFR-7 | 可测试性 | 业务类可独立实例化；核心提供 `reset()` 供用例隔离；提供 `ros_tests` 可执行测试 |
| NFR-8 | 可移植性 | Linux/macOS 可编译（GCC 9+/Clang 10+）；Windows 仅需替换时间函数分支 |
| NFR-9 | 文档 | 需求、架构、技术、用户、测试五类文档齐备，且与代码一致 |

## 8. 约束与假设

- 单进程、单机；节点生命周期由调用方（`main` 或测试）持有，核心不拥有节点对象；
- 消息转发为**同步分发、异步语义**：发布者不等待订阅者"应答"，但订阅者回调在发布调用栈内执行（便于观察，v1 不做消息队列线程化）；
- 时间戳取本机本地时间，精度到秒；
- 中文日志输出依赖 UTF-8 终端，不做编码转换；
- 假设订阅者回调轻量（微秒级），重业务应自行投递到线程池（v1 不提供）。
