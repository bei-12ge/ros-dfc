# 用户手册：如何使用 ros_sim

| 项目 | 内容 |
| --- | --- |
| 面向读者 | 想用本项目理解/演示/二次开发"节点—话题"通信的人（不需要读源码） |
| 阅读顺序 | 第 1 章了解它能做什么 → 第 2 章跑起来 → 第 3 章写自己的节点 → 第 4 章查 API |
| 预计上手时间 | 5 分钟跑通，15 分钟写出自己的发布者与订阅者 |

---

## 1. 这是什么

`ros_sim` 是一个**单进程内的"迷你 ROS 通信内核"**。它不联网、不需要 `roscore`，只用一个可执行文件就能演示：

- 多个**发布者**往同一个**话题**发消息；
- 多个**订阅者**同时接收，各自打印"内容 + 时间戳"；
- 一条消息发给所有订阅者，发布者**不等**任何人应答；
- 所有非法操作（空名字、重复名字、空消息、不存在的话题）都会抛异常并打印错误码，**程序不崩溃**；
- 支持"一问一答"的**服务调用**、带温湿度的**自定义消息**、运行期**加/删节点**、日志**落盘**。

一句话：**它把 ROS 的"发布/订阅"骨架用 C++ 重写了一遍**，方便学习、演示与比赛前的本地调试。

## 3. 五分钟写出你的第一个节点

在项目根目录新建 `my_first_node.cpp`：

```cpp
#include "ros/ros_sim.h"

#include <iostream>
#include <memory>

using namespace ros_sim;

int main() {
    Logger::instance().addFileSink("logs/my_app.log");   // 可选：日志落盘

    // 1) 发布者：节点名 + 话题名
    Publisher publisher("my_pub", "demo/chatter");

    // 2) 订阅者：同话题 + 一个业务回调（回调可为空）
    Subscriber subscriber(
        "my_sub", "demo/chatter",
        [](const Subscriber& self, const std::shared_ptr<const Message>& message) {
            std::cout << self.name() << " 收到: " << message->content()
                      << " @" << message->timestamp() << "\n";
        });

    // 3) 必须先 init，才会注册到核心；不 init 直接 publish 会抛 NODE-003
    publisher.init();
    subscriber.init();

    // 4) 连续发布
    for (int i = 0; i < 5; ++i) {
        const size_t delivered = publisher.publish("hello " + std::to_string(i));
        std::cout << "发布第 " << i + 1 << " 条，送达 " << delivered << " 个订阅者\n";
    }

    // 5) 收尾：全局关闭（也可不写，节点析构时会自动注销）
    ROS::instance().shutdownAll();
    Logger::instance().closeFileSink();
    return 0;
}
```

编译并运行：

```bash
g++ -std=c++17 -Iinclude my_first_node.cpp build/librossim.a -o my_first_node
./my_first_node
```

> 提示：也可以把自己的文件加进 `CMakeLists.txt` 的 `add_executable` 里，用 `cmake --build build` 统一构建。

## 4. API 速查

### 4.1 发布者 `Publisher`

| 接口 | 说明 |
| --- | --- |
| `Publisher(name, topic)` | 构造；空节点名抛 `NODE-001`，空话题抛 `TOPIC-001` |
| `init()` | 注册到核心并打印初始化日志 |
| `shutdown()` | 注销并打印关闭日志；可重复调用 |
| `publish(const std::string&)` | 发字符串：内部创建带时间戳的 `Message` |
| `publish(const Message&)` | 发已有消息对象（做一次拷贝） |
| `publish(const std::shared_ptr<const Message>&)` | **推荐**：无拷贝，且保留 `SensorMessage` 的多态类型 |
| `publishedCount()` | 累计发布条数 |
| `name()` / `topic()` | 只读名称 |

返回值：`publish` 返回**实际送达的订阅者数量**（0 表示当前无人订阅，不算错误）。

### 4.2 订阅者 `Subscriber`

| 接口 | 说明 |
| --- | --- |
| `Subscriber(name, topic, callback = nullptr)` | 构造；回调可为空 |
| `init()` / `shutdown()` | 注册 / 注销 |
| `receive(msg)` | 框架调用，一般无需手动调；会打印含内容与时间戳的日志 |
| `setCallback(cb)` | 运行期替换回调 |
| `receivedCount()` | 累计接收条数 |

回调签名：

```cpp
std::function<void(const Subscriber&, const std::shared_ptr<const Message>&)>
```

回调里**可以**继续发布消息或调用服务；**不要**做长时间阻塞（v1 回调在发布线程内执行）。回调抛出的异常会被框架捕获并记 ERROR，不影响其他订阅者。

### 4.3 核心 `ROS`

| 接口 | 说明 |
| --- | --- |
| `ROS::instance()` | 取全局唯一核心 |
| `registerPublisher/registerSubscriber` | 一般由 `init()` 调用，无需手工调 |
| `publish(topic, msg)` | 直接向话题广播（需先有节点声明过该话题） |
| `topics()` / `nodeNames()` | 当前话题 / 节点列表 |
| `publisherCount(topic)` / `subscriberCount(topic)` | 某话题的发布者 / 订阅者数量 |
| `removeNode(name)` | 运行期删除节点（会走 `shutdown`，输出关闭日志） |
| `shutdownAll()` | 全局关闭所有节点，幂等 |
| `isShutdown()` | 是否已全局关闭 |

### 4.4 服务（加分功能）

```cpp
// 服务端：服务名 + 处理函数（请求串 → 响应串）
ServiceServer server("srv_add", "service/add",
                     [](const std::string& request) -> std::string {
                         return "收到:" + request;
                     });
// 客户端：同步调用，阻塞直到拿到响应
ServiceClient client("cli_add", "service/add");
server.init();
client.init();
std::string response = client.call("ping");   // → "收到:ping"
```

### 4.5 日志

```cpp
Logger::instance().setLevel(LogLevel::WARN);            // 只看 WARN/ERROR
Logger::instance().addFileSink("logs/app.log");         // 落盘（失败会自动降级）
Logger::instance().info("MY_MODULE", "自定义日志");
Logger::instance().logException(ex);                    // 按异常自带级别输出
```

行格式：`[YYYY-MM-DD HH:MM:SS][LEVEL][MODULE] message`，可直接 `grep '[ERROR]' logs/app.log` 定位问题。

## 5. 错误码速查

| 错误码 | 含义 | 我该怎么做 |
| --- | --- | --- |
| NODE-001 | 节点名为空 | 给节点一个非空名字 |
| NODE-002 | 节点名重复 | 改名，或先 `shutdown()` 旧节点 |
| NODE-003 | 节点不存在/已关闭 | 别在 `shutdown` 之后继续用；注意先 `init` |
| TOPIC-001 | 话题名为空 | 补话题名 |
| TOPIC-002 | 话题不存在 | 检查拼写；先让发布者或订阅者 `init` 声明该话题 |
| MSG-001 | 消息内容为空 | 检查数据源是否为空串/纯空格 |
| MSG-002 | 消息对象为空指针 | 检查 `make_shared` 是否成功、别传空 `shared_ptr` |
| MSG-003 | 传感器数值越界 | 温度应在 [-40, 125]，湿度应在 [0, 100] |
| SERVICE-001 | 服务未注册 | 先 `server.init()`，或检查服务名 |
| SERVICE-002 | 服务处理失败 | 看日志里的具体原因（多为请求格式不符） |
| SERVICE-003 | 客户端未 init | 调用前先 `client.init()` |
| ROS-001 | 系统已关闭后注册 | 检查是否已 `shutdownAll()` |

## 6. FAQ

**Q1：发布成功但订阅者没收到？**
按顺序查三件事：① 订阅者是否 `init()`；② 两边话题名是否**完全一致**（区分大小写，注意空格）；③ 是否在 `shutdown()` 之后才发布（此时返回 0 或抛 `NODE-003`）。

**Q2：为什么 `publish()` 返回 0？**
说明该话题当前没有订阅者。消息被丢弃（日志里有一条 WARN），这不算错误——ROS 语义里"没人订阅"本就是正常状态。

**Q3：为什么两个节点不能同名？**
节点名是核心映射表的键，也是日志里的身份标识；同名会导致注册歧义，所以重复注册抛 `NODE-002`。

**Q4：能不能多线程发布？**
可以。核心用互斥量保护注册表，计数用原子变量；4 线程 × 500 条的用例已验证接收条数精确一致。

**Q5：回调太慢会影响谁？**
会影响调用 `publish` 的那个线程（v1 回调在发布线程栈内同步执行）。请保持回调轻量；重活建议自行投递到线程池。

**Q6：`publish(const Message&)` 和 `publish(shared_ptr<const Message>)` 选哪个？**
传 `SensorMessage` 等子类时**必须**用 `shared_ptr` 版本，否则按 `Message&` 传参会发生**对象切片**（多态信息丢失，类型退化为 `std_msgs/String`）。

**Q7：窗口中文乱码？**
源码与日志均为 UTF-8。Windows 旧终端请先 `chcp 65001`。

**Q8：日志文件太大了怎么办？**
v1 是追加写、不自动切分。可定期清空 `logs/`，或后续实现按大小滚动（技术文档 §8 有记录）。

**Q9：节点忘记 `shutdown()` 会怎样？**
不会泄漏注册表项：`Node` 析构函数会自动注销。但**建议显式 `shutdown()`**，这样日志里能看到完整的关闭轨迹。

**Q10：想加一种自己的消息类型？**
继承 `Message` 并覆盖 `typeName()` / `toString()` 即可，转发层不需要任何改动（参考 `SensorMessage`，源码 30 行）。
