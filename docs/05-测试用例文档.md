## 1. 测试策略

### 1.1 分层

| 层次 | 对象 | 目标 |
| --- | --- | --- |
| 单元测试 | `Message`、`Node`、`Publisher`、`Subscriber`、异常、日志 | 每个类独立正确，接口契约不被破坏 |
| 集成测试 | `ROS` 核心 + 节点组合 | 注册—发布—转发—关闭 全链路正确 |
| 并发测试 | 多线程发布 | 无数据竞争、计数精确、无崩溃 |
| 内存检查 | 全部二进制 | ASan/UBSan 零报告 |

### 1.2 用例设计方法

| 方法 | 落地 |
| --- | --- |
| 等价类划分 | 每个参数分"合法 / 非法"两类（如话题名：正常串 vs 空串、纯空白） |
| 边界值分析 | 传感器量程取 `-40 / 125 / 0 / 100` 边界，以及 `125.1 / -1` 越界 |
| 错误推测 | 空指针、重复注册、已关闭仍使用、回调抛异常、删除不存在的节点 |
| 状态迁移 | 未初始化 → 已初始化 → 已关闭 三态下的接口行为 |
| 场景法 | "初始化 → 连续发布 → 动态增删 → 关闭"完整剧本 |

### 1.3 执行方式

```bash
./scripts/run_tests.sh          # 构建并运行，失败返回非 0
# 或
cd build && ./ros_tests
# 或
ctest --test-dir build --output-on-failure
```

失败时输出 `文件:行号 → 断言详情`，并统计失败断言数。

## 5. 缺陷记录（开发过程中真实发现并修复）

| 编号 | 现象 | 定位 | 修复 | 验证 |
| --- | --- | --- | --- | --- |
| BUG-01 | 时间戳格式化触发 `-Wformat-truncation` 警告，违反"零警告"目标 | `timestamp.h` 用 `snprintf("%04d-...")`，GCC 无法证明缓冲区足够 | 改用 `std::strftime("%Y-%m-%d %H:%M:%S")` | 重新构建，警告数 0（提交 `feat(exception,logger)`） |
| BUG-02 | `publisher->publish(nullptr)` 编译报"重载歧义" | `nullptr` 同时可转 `const Message&` 与 `shared_ptr<const Message>` | 调用处显式构造空 `shared_ptr`，并在用户手册 FAQ 注明该调用方式 | 编译通过，`MSG-002` 用例通过 |
| BUG-03 | 注册流程存在同线程重入死锁风险（`registerPublisher` → `registerNode`） | 初版用 `std::mutex` 且两方法各自加锁 | 改用 `std::recursive_mutex`，并把"仅做表操作"写入架构文档纪律 | 全部注册/并发用例通过（ASan 无死锁报告） |
| BUG-04 | 演示程序"调用不存在的服务"用例实际返回 `SERVICE-002` | 用例误用了指向**已存在**服务的客户端对象 | 改为独立 `cli_ghost` 客户端指向 `service/not_exist` | 输出 `SERVICE-001`，符合预期 |
| BUG-05 | 注销订阅者后空话题键残留，`topics()` 仍返回该话题 | 只 `erase` 元素，未回收空 vector 的键 | 注销时判断 `vec.empty()` 则擦除键 | TC-512 断言 `topics().size()==0` 通过 |

> 说明：BUG-01~05 均按"先复现 → 定位 → 修复 → 补用例"的流程闭环，对应提交信息可在 `git log` 中查到。

## 6. 测试结论

1. 48 个用例、114 个断言全部通过，覆盖需求 FR-01 ~ FR-08 的全部 P0 条目与 P1 加分项；
2. 10 类非法操作（空名、重复名、空消息、空指针、不存在话题、不存在节点、未初始化、不存在服务、服务内部异常、重复服务）均"抛异常不崩溃"，符合需求 FR-08；
3. 4 线程并发发布的计数与 ASan/UBSan 结果证明核心路由在并发场景下无数据竞争、无内存错误；
4. 日志落盘与级别过滤行为符合 FR-07.4/07.5；
5. 结论：**达到可提交状态**。残余风险为"文件不可写分支未构造用例"（已在覆盖率表中标注为已知缺口，建议 v1.1 补充）。
